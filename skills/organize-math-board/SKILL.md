# 数学板书整理

## 输出与内容

- 默认交付同名 .md 与 .pdf，使用简短客观的文件名；以完成的 Markdown 为唯一内容来源。
- 直接从板书第一个知识点开始。沿用板书标题、小节、Note 编号、①②、$1^\circ$ 等题号及其顺序，不自拟总标题、封面、概述、总结或结尾引导。不要按自己的知识分类重新编排。
- 还原各栏的实际阅读顺序，识别跨图续写与重复内容。合并重复拍摄的同一段，不合并板书中不同编号的内容。保留条件、取等条件、例题、推导和老师标注。
- 保留变量与记号约定，包括用 $x$ 表示数列极限、不同邻域记号及无穷符号。不擅自改成自己习惯的符号。
- 将板书正文与补充解释分开。把符号、量词、反例、适用条件与省略步骤的说明放在对应位置的独立“注解”引用块；PDF 自动渲染为浅底色文本框。不要把自己补充的证明写成板书内容。
- 根据难度和用户要求增加必要解释，不规定每节必须有批注或固定段数。自补例子、证明分别注明“补充例子”“补充证明”。
- 用户只要求改善排版时，保留已有数学内容、措辞、顺序和编号，仅调整格式；需要纠正内容时在注解中说明。
- 不把照片文件名、工具引用、图片占位符或套话放进笔记；不使用“不是 A 而是 B”式强调句。

## 读图与数学核对

1. 批量检查图片是否实际可用，再逐张查看。路径失效时用本次附件的已知文件 ID 恢复，不重复尝试失效路径，不拿历史同名图片替代。
2. 先列出板书的标题、编号和跨图接续，再转录。核对上下标、正负号、括号、端点、量词、变量范围、不等号以及矩阵与行列式维数。
3. 若看不清的符号或缺图会改变数学结论，立即问一个能定位的具体问题，等待答案后处理该处；其余可确认内容可继续。非关键文字标明“原图此处不清晰”。
4. 核对定义、推导、取等条件和教材约定。明确的板书错误应在邻近注解中写明原式与正确式；无法确定时先问，不偷偷修正。
5. 写完后按原编号逐项对照图片检查，不依靠 OCR 或一份概述替代全部读图。

## Markdown 结构

- 使用 UTF-8，章节 ##、小节 ###；标题与编号取自板书。未编号的段落不新增编号。正文左对齐，不以空格或 Tab 制造缩进。
- 行内数学用 $...$，独立公式用单独成行的 $$ 包围。保留 LaTeX 源码；用 aligned、cases、pmatrix、vmatrix 等组织多行式。公式内中文用 \text{中文}。
- 保留板书中条件与结论的相邻关系。长公式在数学上合理的位置断行，不把长中文定理塞进不换行的数学框。
- 注解统一写为引用块，首行 **注解：具体问题**；引用块内部每一行（包括公式与空行）都带 >。结束后添加一个不带 > 的空行，再恢复板书正文，防止后续题号被吸入注解。
- 在长注解中按证明阶段写明确的小标题，供渲染器按语义分段。需要手动调整时可分成相邻的“注解：……”和“注解：……（续）”，不改写正文。
- 只用表格表达适合对照的内容，不用表格强行排整页正文。单元格中的绝对值写 \lvert、\rvert，避免 | 破坏分列。
- 对照 [内容与注解示例](references/style.md)；不把示例里的标题或题号套进本次板书。

## PDF 生成与检查

1. 按当前 PDF 技能执行生成标记；最终笔记按当前 Library 技能保存。技能更新走个人技能的 Git 保存机制。
2. 尽早一次检查 Pandoc、XeLaTeX、xeCJK、tcolorbox、中文字体和 Poppler。沿用已可用的字体和 TeX 目录，不重复下载。缺依赖时读 [渲染说明](references/rendering.md)。
3. 直接使用本技能 scripts/render_pdf.py 与随附模板，不为每次任务复制并重写渲染脚本：

   ~~~bash
   python3 <skill-dir>/scripts/render_pdf.py <notes.md> --output <notes.pdf> \
     --build-dir <scratch>/math-build --preview-dir <scratch>/math-preview
   ~~~

   显式字体或局部 TeX 包加 --font-file、--bold-font-file、--tex-inputs。
4. 沿用默认 A4、11pt 正文、统一左边界、固定公式间距和注解文本框。让短板书段落与对应注解成组分页；长注解按已有小标题分段并标“续”。过高内容允许自然跨页，不强塞进整页不可拆框。
5. 自动检查注解分隔、缺字、水平及垂直溢出、字体嵌入和中文提取。自动检查通过仍须视觉检查。
6. --preview-dir 一次生成所有页 PNG 和联系表。先扫联系表检查密度，再逐页查看截图，可批量显示多页；重点检查复杂公式、表格、注解框、页首与页尾。
7. 修复标题悬空、条件与结论断开、短注解跨页、公式或边框截断、仅剩一两行的尾页、语义单元被拆开造成的大块留白。正常收尾的末页不要求填满；不要为减页数缩小字号。
8. 修改前定位缺陷，优先调整语义分段；不要盲试多组页边距。用保留的 TeX/log 定位问题；修复后重新生成截图，避免把旧预览当作最终 PDF。
9. 按原编号核对 .md 与 .pdf 的定义、公式、例题一致，再保存两份最终文件。说明无法验证的限制，不把编译成功当成视觉检查成功。

## 提速

- 将独立的图片恢复、依赖检查和技能资源读取合并批量执行；数学内容、编辑与渲染保持依赖顺序。
- 先完成转录与数学核对，再排版；用户仅改版式时直接复用已有 Markdown。
- 一次运行完成排版、验证、所有页截图和联系表；复用 --build-dir 中的辅助文件，脚本只在日志要求时额外编译。
- 发现缺陷只修对应问题，不重写全文、不重新安装可用依赖、不重复全套数学检查。内容改动才触发相应的数学复核。
- 截图检查保留证据后及时交付，不为已通过的版面重复运行相同检查；不承诺整项任务的固定耗时。

## 交付

默认只给 .md 与 .pdf 下载链接，可附一句完成说明。用户没有要求时不在聊天重贴全文、不追加建议或反问。用户另行要求总结或技能修改时，回应该请求。
