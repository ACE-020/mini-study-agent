# 知错 · 学习整理助手（mini-study-agent）

用 Python、大模型 API 和本地 JSON，跑通“整理错题 → 保存 → 下次按错题复习”。主要目的是理解工具调用、上下文、持久化和失败处理，并留下可用于面试讲解的运行证据。

目前提供统一学习原稿录入、错题本、笔记库、跨库选择分析、命令行、本机网页和资料题库。布局依据见 [UI_LAYOUT.md](UI_LAYOUT.md)，各任务的画面取舍与切换规则见 [UI_TASKS.md](UI_TASKS.md)。笔记整理默认使用项目内的 organize-math-board skill，详见 [笔记功能与工具说明](NOTES.md)。默认逐步引导，不直接给完整解法；当前题的巩固与历史错题复习分开。用户已于 2026-10-20 提供真实模型日志，验证了普通问答、检索笔记、保存错题及跨进程读取后出题，详见 [验收记录](VALIDATION.md)。离线演示仍使用固定脚本；数学正确性与错因归纳需要人工核对。

### 首次安装与启动

先安装 Python（本项目在 Windows / Python 3.12 验证）。解压源码包，在能看到 README.md 与 requirements.txt 的项目目录中打开终端。不要直接复制别人的 .venv。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe web.py --open
```

macOS / Linux（提供启动方式，尚未在这些系统完成整套验收）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python web.py --open
```

启动后访问 http://127.0.0.1:8765，在“模型设置”填写自己的服务地址、API Key 和模型名称。完整功能使用真实 API，会消耗该 Key 的额度；离线 demo 和自动测试使用替身，不能代替真实功能体验。整理模型需支持工具调用；整理图片原稿时也需支持图片输入，OCR 模型需支持图片输入。不要只验证文字连接就认为识图也已经可用。

PDF 导出需要 Chrome、Edge 或 Playwright 的 Chromium。没有可用浏览器时，在对应虚拟环境执行 `python -m playwright install chromium`（Windows 使用 `.\.venv\Scripts\python.exe`，macOS/Linux 使用 `.venv/bin/python`）。中文 PDF 还需要系统中文字体；Windows 默认使用微软雅黑，其他系统可准备 Noto Sans CJK 等字体。

可在 Windows 双击 start_web.cmd 再次启动。关闭服务窗口会停止网页；修改 Python 后应停止旧服务并重新启动。127.0.0.1 只指当前电脑，不能把此地址发给别人作为在线体验链接。

## 当前范围

- 输入文字题目、自己的答案和参考答案，或明确标注的错误；信息不足时追问。
- `search_notes(query)`：按关键词检索 `data/notes.json`，最多返回 5 条笔记。
- `save_mistake(...)`：保存原题、用户答案、正确答案、错误原因和知识点。
- `get_mistakes(topic?, limit?)`：读取本地错题，优先返回错题数量较多的知识点。
- `pick_exercise(topic, exclude_id?, exercise_id?)`：从已确认的资料题库选择同知识点原题，只返回题干与来源。
- `save_note(topic, content)`：保存完整 Markdown 笔记，并默认导出 Markdown/PDF；保存后可通过 search_notes 检索。
- `delete_records(items)`、`merge_records(items, topic, content)`：只生成针对本轮所选内容的待确认删除或合并预览，用户在网页核对确认后才执行。
- 支持多选图片、PDF、TXT、Markdown。学习原稿可混合笔记与错题，资料题库核对后写入 `data/exercises.json`。
- 当前题追问禁止读取其他历史错题；历史复习入口才允许按错题分布选方向。练习不再由模型创编，默认不展示答案。

“调整复习内容”在第一版中指**根据已有错题选择知识点**。尚未实现记录复习作答、自动掌握度评分或间隔重复。相同题目与错误答案不重复保存；再次提交不会增加错误次数。

真正注册给模型的工具共 **7 个**；`_read`、`_write_mistakes` 是内部辅助函数，`execute` 是白名单分发器，不是额外工具。

先支持单用户、单进程；图片、PDF、TXT 和 Markdown 输入、笔记 Markdown/PDF 导出已支持。PDF 每批最多 20 页，支持指定页码；向量检索和掌握度更新尚未实现。关键词检索不是语义检索；模型对高数的判断也需要核对。

## 配置真实模型

使用支持函数工具调用的 Chat Completions 兼容接口。下面以 DeepSeek 官方接口为例；模型名称和权限以供应商当前文档与账户为准。其他供应商需要替换地址与模型名称，兼容性仍需实际验证。

```powershell
$env:LLM_BASE_URL="https://api.deepseek.com"
$env:LLM_MODEL="deepseek-v4-pro"
# 交互输入密钥，不把密钥写进命令历史、源代码或聊天中。
$credential = Get-Credential -UserName "api" -Message "密码栏输入 API Key"
$env:LLM_API_KEY=$credential.GetNetworkCredential().Password

python main.py --prompt "你好，请说明你能做什么。"
python main.py --input-file examples/homework.txt --trace
python main.py --prompt "根据我以前的错题出一道复习题，先不要给答案。" --trace
```

这些环境变量只影响当前终端。也可直接运行 `python main.py` 进入连续对话，输入 `/exit` 退出。对话上下文只在当前进程内保留；错题 JSON 跨进程保留，模型需要调用工具才能读取它。第一次成功保存时创建 `data/mistakes.json`。

## 五个问题分别在哪里看

1. **模型为什么调用工具？** 请求同时携带用户内容、系统提示词和工具说明（包括参数格式）。模型生成工具调用消息。程序能观察工具名、参数及结果；不能仅凭日志声称知道模型内部的完整判断原因。修改工具说明再对照运行，可以研究行为变化。
2. **谁执行？** `tools.py` 中的 Python 函数执行；模型本身不能读写本地 JSON。`agent.py` 只接受白名单内的工具，当前题模式额外禁止 get_mistakes。
3. **结果怎样返回？** 对于模型调用的工具，保存原始 assistant 工具消息，再追加带 `tool_call_id` 的结果，继续请求模型。对于已确定知识点的资料选题，程序直接调用选题工具并原样展示题干，不再请求模型改写；日志的 selected_by 区分 program 与 model。
4. **数据怎样保存？** `save_mistake` 生成稳定 ID 并写入 JSON。先写同目录临时文件，再替换原文件。去重可避免同一次错题被重复保存；这是单进程实现，不支持并发写入。
5. **失败怎么办？** 网络超时、408、429、5xx 最多重试两次；鉴权或参数等其他 HTTP 错误直接报告。工具参数错误和文件错误交回模型，本轮最多请求模型六次。模型最终回复失败时，已经写入的错题保留；未完成的一轮不会留在内存对话历史里。

函数调用的“模型返回调用 → 应用执行 → 结果交回模型”流程参见 [DeepSeek 官方工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)。不同供应商的协议细节需要分别核对。

## 逐步教学与资料选题

右上角“助手规则”可查看实际提示词。默认每次只给一步提示并等待回答；用户明确要求完整解法时才完整讲解。左侧“练习资料”支持批量 PDF、图片、UTF-8 TXT/MD 或粘贴文字，按“上传 → 后台整理 → 核对并确认入库”建立电子题库，支持导出 JSON。PDF/图片默认直接从原图拆题，读取文字是可选入口。可用 examples/practice-material.txt 试用。

“复习练习”按大分类 → 细分标签组织已收录的资料题与错题，选定后本机读取对应原题。“出”“再来一道”默认选现有题；明确说“你自己出一道吧”才进入 AI 生成模式，保留当前知识点，标明来源并先不给答案。换题清理上一题上下文，继续追问保留当前题。详见 [TUTORING.md](TUTORING.md)。

## 资料导入更新（2026-10-23）

导入区按“上传/原文 → 后台整理 → 核对入库”分步显示，手机为单列，电脑预览为双列，滚动区域限高。后台任务只生成预览，不自动入库；可继续浏览、练习或提交另一批。每个浏览器会话最多 4 批待处理，全局最多同时处理 2 批；任务与原文保留约 2 小时，重启服务后消失。未确认的手动编辑仍是当前页面草稿，刷新会丢失。

题目数以程序实际收到的预览为准，识别疑点与分段说明单独展示。修正了旧规则“最多返回 20 题”和分段合计数量混淆的问题；题目预览/入库每批上限为 200 题，PDF 每次读取最多 20 页，两种限制不同。AI 校正仅提出当前批次的字段修改，确认应用到预览后，仍需确认入库；不会修改已收录记录。

资料题库现在支持手动添加、编辑校正、二次确认删除、搜索、跨页选择、问 AI 和所选内容导出。编辑保持题目 ID，发现其他页面已修改时拒绝覆盖。跨库删除包含资料题，并有恢复快照。错题与练习题仍分别保存在 mistakes.json / exercises.json；统一题库与错题属性、内置北邮题集属于后续方案，尚未实现。

实现入口：material_jobs.py（后台队列）、materials.py（拆题/校正/题库）、web.py（会话与接口）、static/materials.js + static/material-workflow.css（分步界面/任务浮窗/核对）、library.py + static/library.js（跨页选择与确认操作）。验收入口：tests/test_material_workflow.py 和 tests/browser_material_workflow.cjs。

## 原图整理、逐题校正与来源（2026-10-23）

练习资料选择 PDF / 图片后，默认点击“直接从原文件整理”即可提交后台任务，不需要先转写。系统在本机将选定页渲染为原图，用已配置的图片模型直接生成结构化题目，并提供整页与交叠局部细节；不会因为 PDF 有文字层而跳过原图。纯 TXT/MD/粘贴仍走文字路径。“转成文字”保留为可选入口。一次请求包含若干原页及相邻页上下文，复杂跨页题仍需核对。

核对页显示本次服务运行中的批次编号、提交时间、文件名和原样填写的页码范围；入库记录保留来源元数据。每题尽量关联源页索引，不能确认时不编造。疑点旁、预览头部和每张题卡/编辑区都有 AI 修正入口：电脑侧栏与题目并排，窄窗口以可关闭弹窗显示。可以指定单题、参考页，查看原始页面，或补充一张局部图；先核对修改对照，再应用，最后确认入库。未授权的其他会话不能读取原页。

公式要求规范 LaTeX，并在预览、已有题目和修改对照中渲染。旧的裸 LaTeX 可补展示标记；已经变成 x2 / ex、根号范围丢失的内容不会由显示代码猜回，需对照原图重新整理或校正。入库后后台任务移除时，原页图像不随题库永久保存，来源文件名和页码仍保留。

图片模型与文字模型可分别配置。DeepSeek 官方文档当前列出 deepseek-flash 支持 Vision，deepseek-v4-pro 不支持；原图整理使用图片模型，程序会拦住官方 DeepSeek Pro 的图片配置，不静默丢弃图片。外部自定义服务的能力需要用户验证。

经用户明确授权，仅对所给第 6 题局部截图做过一次真实 DeepSeek Flash 识别：指数 a/(x-1)、分段条件、嵌套根号均与原图一致，没有解题、没有写入题库。该样例通过不能代表整页小字、手写或所有题目的准确率。流程验收和真实识别的边界详见 VALIDATION.md。

标签与归属现已分开：paper 保存试卷/题组，tags 保存细题型，topic 仍为知识点。支持手动编辑、跨页多选归类和筛选，见后续更新及 SOURCE_AND_TAGS.md。


## 连续修正、分页与细标签（2026-10-23）

两个入口共用原图准备和视觉输入，添加学习内容可以直接读图，无需先转写。练习资料支持一次最多20页，由后台每2个主页面分段；混合整理一轮保留最多20页。预览/资料库每页渲染20道题，跨页勾选保留。每题仅一个AI入口。打开后进入宽屏并排核对工作区：左上原题列表可自由滚动，左下连续修正对话，右侧原页独立滚动与缩放；不增加上一题/下一题流程。返回恢复原列表的分页和滚动位置。修正携带最近对话，确认后才应用。原页支持本批所有页、可关闭跟随、跳到本题或已知答案页；中间分隔线可调宽度。

## 试卷身份、疑点定位与整批答案汇总（2026-10-24）

核对区顶部固定显示前20题/后20题和范围；题卡单独显示原题节号与小题号、保留带编号的完整试卷名。滚动左侧会跟随当前浏览题目，AI修正范围独立明确显示，避免浏览时自动改写未发送问题；也可以关闭跟随。点原页题干/答案框或识别疑点链接，可双向跳转并标黄，不自动请求模型。

原生单列PDF的文字层仅提供标题、题号和坐标，数学题干仍从原图识别。照片/无可靠原生坐标可用模型给出的规范区域，缺少区域时明确提示、不假装精准。新增answer_fragments将答案页读到的内容带回，全批处理后按来源文件、完整试卷身份和原题号关联；本段未见不当成整批缺失。内部处理说明和已解决的缺答案提示不进入疑点列表，真实冲突仍保留。

## 导入容量与就近反馈（2026-10-24）

直接整理与可选转文字统一每批20页，自动续传从21–40这样的小段继续；后台仍每2个主页面分段整理。前端根据服务器提供的同一上限校验，手填过大范围不上传；后端在渲染前拒绝超页数，不静默截掉选中的页。页面图片自动控制体积，避免允许20页却在末尾触发40MiB错误。

直接整理按钮旁增加持续等待动画和秒数，准备期间锁定本批输入；失败保留文件、页码和补充文字，错误在按钮旁显示。转文字报错只在转文字按钮旁显示，不再复制到页顶。TXT/MD可直接读取文字、无需转图，仍有每批80000字和分段整理限制，不保证整本MD一次模型调用。

主要文件：material_sources.py、static/material-submission.js、static/material-reading.js。验收：tests/test_material_capacity.py、tests/browser_material_capacity.cjs。升级前保存尚未入库的预览，再重启本机程序并刷新页面。

## 答案双向定位与固定原页入口（2026-10-24）

“查看原页 / 收起原页”位于核对窗口标题下方同一位置、使用相同样式。点击左侧“核对参考答案”或答案正文可定位原答案页；右侧点击答案框会展开并显示左侧对应答案。题干与答案分别跟随，不再将答案点击解释为题干点击。手动翻右侧原页后，左侧被动滚动不覆盖所选页；点击具体题干/答案或重新勾选跟随可恢复定位。浏览不自动调用模型。

## 导入失败恢复、原文件与所选页预览（2026-10-24）

旧提示把模型JSON/字段校验失败也写成“原文不完整”。现在区分返回内容解析、字段校验和网络失败，并记录实际失败的文件页；可选元数据null按未提供处理。无法从旧版笼统提示还原当次具体字段，不把该提示当作PDF缺页的证据。

PDF每两个主页面的成功结果随任务保留，失败时仍展示其余已完成题目。用户点击“重试未完成部分”后仅重新请求失败部分，成功部分复用，再汇总题干和答案；不默认增加自动识图重试。未确认的内容仍不写入学习库。取消后重试使用独立令牌，旧请求不能覆盖新结果。

原文件按任务在本机临时保留，服务运行期间切换任务、刷新网页后可恢复，并支持后续页码、转文字、全文预览；空文件框不再被误认为原文件已丢失。缓存闲置2小时过期，关服务后清理，全局最多512MiB；任务原页仍独立保留到任务移除/过期。清空当前导入区不删除后台任务依赖的原文件。已入库的题目不永久保存原文件。

PDF页码旁增加“预览所选页”，仅浏览当前填写的范围；上方文件旁的全文预览保留。自动续传使用当前任务的原文件和来源页码，不依赖最后一次上传。主要文件：material_files.py、material_jobs.py、static/material-recovery.js；验收：tests/test_material_recovery.py、tests/browser_material_recovery.cjs。

核对时可逐条隐藏已检查的提示，用一个“显示上一条”按钮依次撤回；题目/AI修正的上下高度和题目/原页的左右宽度均可拖动，浏览器记住比例。详见 WEB_GUIDE.md。
